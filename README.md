# GSM 07.10 MUX Terminal

Терминал для Windows, который сам реализует мультиплексор **GSM 07.10 / 3GPP TS 27.010 (Basic Option)** на одном
COM-порту и раскладывает логические каналы (DLC) по независимым вкладкам. Сторонние драйверы не нужны.

```
[ Модем ] ──COM-порт (байтовый поток 07.10)──► [ MuxSession: FrameParser + запись под замком ]
                                                   ├─► DLC0  управление ─► вкладка «System Log» (сырые кадры HEX)
                                                   ├─► DLC1  ─► вкладка «DLC 1 · AT»
                                                   ├─► DLC2  ─► вкладка «DLC 2 · Data/SMS»
                                                   └─► DLC3  ─► вкладка «DLC 3 · GPS/NMEA»   (+ любые 1..63)
```

## Возможности

* Перевод модема в MUX (`AT+CMUX=…`), открытие DLC0 и каналов данных (SABM → UA), корректное закрытие (DISC + CLD —
  модем возвращается в AT-режим без перезагрузки).
* Приём: потоковый разбор кадров, проверка FCS, ресинхронизация после мусора и битых кадров, маршрутизация по DLC.
* Передача: UIH-кадры, автоматическая нарезка по N1, потокобезопасная запись (кадры разных вкладок не перемешиваются).
* Канал управления DLC0: ответы на MSC / Test / PN / FCon / FCoff / CLD, NSC на неизвестные команды, учёт flow control.
* Вкладки: независимый скролл, «Очистить», Текст / HEX, время, локальное эхо, перенос строк; ввод с историей (стрелки вверх/вниз),
  выбор окончания строки (CR / CRLF / LF), HEX-ввод, Ctrl+Z (текст из строки + 0x1A — отправка SMS) / Esc.
* System Log: сырые кадры в HEX, служебный обмен DLC0, ошибки FCS; фильтр «Кадры данных» скрывает поток данных каналов.
* **Оформление вывода** (меню «Настройки» → «Отображение и подсветка…», `Ctrl+Shift+S`):
  * фон и основной цвет текста, моноширинный шрифт и размер (в списке — только моноширинные шрифты), темы «Тёмная»,
    «Светлая», «Классическая»;
  * по типам текста — принятые данные, отправленные команды, дата/время, системные сообщения терминала, ошибки:
    свой цвет, фон, жирный/курсив, свой моноширинный шрифт; выделение каждого типа отключается, а время и системные
    сообщения можно скрыть совсем;
  * формат даты/времени (`HH:mm:ss.fff`, `dd.MM.yyyy HH:mm:ss.fff` или свой).
* **Поиск и «Копилка»:** правила (текст или регулярное выражение, регистр, цвет, фон, жирный) подсвечивают совпадения
  во всех вкладках; строки правил с флажком «В копилку» собираются во вкладку «Копилка» — время, канал, правило, строка;
  фильтр по правилу, копирование, сохранение в файл, двойной щелчок — переход к вкладке-источнику. Правило выше
  в списке имеет приоритет; есть проверка шаблона на тестовой строке. Готовые правила: ERROR / +CME / +CMS ERROR,
  RING / +CLIP, +CMTI (новая SMS), NO CARRIER / BUSY, эхо AT-команд, OK, URC (`+XXX:`).
* `Ctrl+F` в любой вкладке — поиск по тексту вывода.
* **Окна (AvalonDock):**
  * вынести вкладку в отдельное окно — перетащить заголовок за пределы окна, кнопка «В окно», `Ctrl+Shift+O` или меню «Окна»;
  * вернуть во вкладку — кнопка «Во вкладку», `Ctrl+Shift+T`, перетащить обратно или «Dock as Tabbed Document» в меню вкладки;
  * разделить окно — перетащить вкладку на маркер у края, кнопки «Справа» / «Снизу» или ПКМ → New Tab Group;
  * «Собрать все окна во вкладки» и готовая раскладка «лог слева, каналы справа».
* Открытие/закрытие отдельных каналов на лету, дополнительные DLC (кнопка «+ Открыть канал»).
* **Эмулятор модема** (пункт «Эмулятор модема» в списке портов) — проверка без железа: AT-команды, SMS
  (`AT+CMGS="…"` → текст → Ctrl+Z), NMEA раз в секунду на DLC3, `AT+BINTEST` — бинарные 0x00..0xFF (в т.ч. 0xF9).
* Сохранение содержимого вкладки в файл, запоминание настроек подключения.

## Платформа: Windows 7 и новее

Приложение собирается под **.NET Framework 4.8** — это последняя версия .NET, которая работает на Windows 7
(.NET 5–8 на Windows 7 не запускаются).

* Windows 7 SP1 / 8.1: нужно один раз установить .NET Framework 4.8
  (офлайн-установщик `ndp48-x86-x64-allos-enu.exe` с сайта Microsoft).
* Windows 10 (1903+) / 11: .NET Framework 4.8 уже есть в системе.

## Сборка для клиента — один файл

```
./build-release.sh          # Linux/macOS, нужен .NET SDK 8
# или на Windows:
dotnet build src\MuxTerminal.App -c Release
```

Результат — `dist/MuxTerminal.exe` (~1 МБ). Все библиотеки (AvalonDock, AvalonEdit, System.Memory, ядро протокола и т.д.)
встроены в exe с помощью Costura.Fody. Клиенту передаётся только этот файл: установка не нужна, настройки
сохраняются в `%AppData%\MuxTerminal\settings.json`.
Рядом лежит `MuxTerminal.exe.config` — его можно не передавать (он лишь фиксирует версию .NET Framework 4.8).
Там же `LICENSE` и `THIRD-PARTY-NOTICES.txt`; их тексты встроены и в exe (меню «Справка» → «О программе»).

GitHub Actions (`.github/workflows/build.yml`) на каждый push собирает exe на Windows, прогоняет тесты
(net8.0 и net48) и выкладывает артефакт `MuxTerminal-exe`.

## Сборка для разработки

```
dotnet build MuxTerminal.sln            # Debug: src/MuxTerminal.App/bin/Debug/net48/
```

## Разработка и проверка на Linux

**Тесты протокола** — под .NET 8 и под .NET Framework 4.8 (через Mono):

```
dotnet test tests/MuxTerminal.Core.Tests -f net8.0
sudo apt install mono-runtime
mono ~/.nuget/packages/xunit.runner.console/2.9.2/tools/net472/xunit.console.exe \
     tests/MuxTerminal.Core.Tests/bin/Debug/net48/MuxTerminal.Core.Tests.dll
```

**Сама программа в Wine:**

```
sudo apt install wine winetricks
export WINEPREFIX=~/.wine-mux
winetricks -q dotnet48 corefonts   # настоящий .NET Framework 4.8 + шрифты Windows (Courier New и др.)
                                   # (без dotnet48 Wine использует встроенный wine-mono — тоже работает)
wine dist/MuxTerminal.exe
```

COM-порт в Wine — это символическая ссылка на устройство Linux (пользователь должен быть в группе `dialout`):

```
ln -s /dev/ttyUSB0 ~/.wine-mux/dosdevices/com3    # в программе выбрать COM3
```

Строки `fixme:…` в консоли Wine — нормальный шум, на работу не влияют.
Без шрифтов Windows в префиксе программа сама выбирает любой установленный моноширинный шрифт
(настоящий WPF падает, если заданный шрифт не найден, — это учтено).

Проверено в Wine 9.0 + wine-mono 8.1: запуск MUX с эмулятором, AT-команды и SMS в каналах, поток NMEA,
разделение окна, вынос вкладки в отдельное окно и возврат, корректная остановка (DISC + CLD).
Что Wine не проверяет: поведение драйвера конкретного USB-модема в Windows 7 — финальная проверка на машине клиента.

## Уточнения к ТЗ (что сделано иначе и почему)

1. **Byte stuffing в Basic Option отсутствует.** Экранирование (0x7D, флаг 0x7E) есть только в Advanced Option
   (`AT+CMUX=1`). В базовом режиме границы кадра задаёт поле Length, поэтому 0xF9 внутри Payload/FCS допустим
   и корректно разбирается. Парсер не ищет «следующий 0xF9» как конец кадра — он читает ровно Length байт и проверяет,
   что за FCS стоит 0xF9. Advanced Option явно отклоняется с понятной ошибкой.
2. **Номер канала — `Address >> 2`**, но бит C/R важен: команды инициатора (наши SABM/DISC/UIH) идут с C/R=1,
   наши ответы (UA на SABM/DISC модема) — с C/R=0. Эталон: `F9 03 3F 01 1C F9` (SABM DLC0), `F9 07 3F 01 DE F9` (SABM DLC1).
3. **FCS:** CRC-8 с полиномом x⁸+x²+x+1 (отражённый 0xE0), старт 0xFF, результат инвертируется; при проверке
   остаток должен быть 0xCF. Для UIH — по Address/Control/Length, для остальных типов — плюс данные.
4. **N1 берётся из команды AT+CMUX** (4-й параметр, по умолчанию 31), и длинные данные режутся на кадры ≤ N1.
   Отдельное поле «N1» в UI не нужно — оно не может расходиться с тем, что получил модем.
5. **Длина 2 байта** нужна только при N1 > 127; поддерживается в обе стороны.
6. **MSC после открытия канала.** Многие модемы (Quectel, SIMCom, u-blox) не отдают данные в канал, пока не получат
   MSC с RTC/RTR. Терминал отправляет его сам и отвечает на MSC модема.
7. **Закрытие MUX:** DISC для каналов данных, затем CLD. Без этого модем остаётся в MUX и не понимает AT до перезагрузки.
8. **Перед AT+CMUX отправляется `AT`** (до 3 попыток) — проверка связи/автобода; опция «Модем уже в MUX» пропускает
   AT+CMUX, если модем остался в MUX после сбоя.
9. **Вкладки не закрываются крестиком** — канал нельзя «потерять»; их можно только перемещать, выносить и разделять.
10. **Синхронизация записи** — `SemaphoreSlim` на порт (один кадр = одна запись), плюс замок на канал, чтобы длинная
    посылка, нарезанная по N1, не перемежалась с другой посылкой того же канала. Цикл чтения никогда не ждёт этих замков,
    поэтому flow control модема не может вызвать взаимоблокировку.

## Статус проверки

* 40 автотестов ядра проходят и под .NET 8, и под .NET Framework 4.8 (Mono): эталонные кадры из документации
  Quectel/SIMCom, разбор с мусором, битыми и разрезанными кадрами, 0xF9 в данных, полный цикл сессии против эмулятора,
  конкурентная запись из разных каналов.
* Интерфейс проверен в Wine (см. выше), включая раскраску, настройки, правила и «Копилку».
* На реальном модеме и на реальной Windows 7 не проверялось. Если модему нужны особые параметры, укажите их в поле
  «Команда», например `AT+CMUX=0,0,5,127,10,3,30,10,2`.

# GSM 07.10 MUX Terminal

Терминал для Windows, который сам реализует мультиплексор **GSM 07.10 / 3GPP TS 27.010 (Basic Option)** на одном
COM-порту и раскладывает логические каналы (DLC) по независимым вкладкам. Сторонние драйверы не нужны.

```
[ Модем ] ──COM-порт (байтовый поток 07.10)──► [ MuxSession: FrameParser + запись под замком ]
                                                   ├─► DLC0  управление ─► вкладка «System Log» (сырые кадры HEX)
                                                   ├─► DLC1  ─► вкладка «DLC 1 · AT»
                                                   ├─► DLC2  ─► вкладка «DLC 2 · Data/SMS»
                                                   └─► DLC3  ─► вкладка «DLC 3 · GPS/NMEA»   (+ любые 1..63)
```

## Возможности

* Перевод модема в MUX (`AT+CMUX=…`), открытие DLC0 и каналов данных (SABM → UA), корректное закрытие (DISC + CLD —
  модем возвращается в AT-режим без перезагрузки).
* Приём: потоковый разбор кадров, проверка FCS, ресинхронизация после мусора и битых кадров, маршрутизация по DLC.
* Передача: UIH-кадры, автоматическая нарезка по N1, потокобезопасная запись (кадры разных вкладок не перемешиваются).
* Канал управления DLC0: ответы на MSC / Test / PN / FCon / FCoff / CLD, NSC на неизвестные команды, учёт flow control.
* Вкладки: независимый скролл, «Очистить», Текст / HEX, время, локальное эхо, перенос строк; ввод с историей (↑/↓),
  выбор окончания строки (CR / CRLF / LF), HEX-ввод, кнопки Ctrl+Z / Esc для SMS.
* **Окна (AvalonDock):**
  * вынести вкладку в отдельное окно — перетащить заголовок за пределы окна, кнопка `⧉`, `Ctrl+Shift+O` или меню «Окна»;
  * вернуть во вкладку — кнопка `▭`, `Ctrl+Shift+T`, перетащить обратно или «Dock as Tabbed Document» в меню вкладки;
  * разделить окно — перетащить вкладку на маркер у края, кнопки `◫` (справа) / `⬓` (снизу) или ПКМ → New Tab Group;
  * «Собрать все окна во вкладки» и готовая раскладка «лог слева, каналы справа».
* Открытие/закрытие отдельных каналов на лету, дополнительные DLC (кнопка «+ Открыть канал»).
* **Эмулятор модема** (пункт «Эмулятор модема» в списке портов) — проверка без железа: AT-команды, SMS
  (`AT+CMGS="…"` → текст → Ctrl+Z), NMEA раз в секунду на DLC3, `AT+BINTEST` — бинарные 0x00..0xFF (в т.ч. 0xF9).
* Сохранение содержимого вкладки в файл, запоминание настроек подключения.

## Сборка и запуск

Нужен .NET 8 SDK.

```
dotnet build MuxTerminal.sln
dotnet test tests/MuxTerminal.Core.Tests
dotnet run --project src/MuxTerminal.App
```

Готовый один `MuxTerminal.exe` (без установки .NET):

```
dotnet publish src/MuxTerminal.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:EnableCompressionInSingleFile=true -o publish
```

GitHub Actions (`.github/workflows/build.yml`) собирает его на каждый push — артефакт `MuxTerminal-win-x64`.

## Уточнения к ТЗ (что сделано иначе и почему)

1. **Byte stuffing в Basic Option отсутствует.** Экранирование (0x7D, флаг 0x7E) есть только в Advanced Option
   (`AT+CMUX=1`). В базовом режиме границы кадра задаёт поле Length, поэтому 0xF9 внутри Payload/FCS допустим
   и корректно разбирается. Парсер не ищет «следующий 0xF9» как конец кадра — он читает ровно Length байт и проверяет,
   что за FCS стоит 0xF9. Advanced Option явно отклоняется с понятной ошибкой.
2. **Номер канала — `Address >> 2`**, но бит C/R важен: команды инициатора (наши SABM/DISC/UIH) идут с C/R=1,
   наши ответы (UA на SABM/DISC модема) — с C/R=0. Эталон: `F9 03 3F 01 1C F9` (SABM DLC0), `F9 07 3F 01 DE F9` (SABM DLC1).
3. **FCS:** CRC-8 с полиномом x⁸+x²+x+1 (отражённый 0xE0), старт 0xFF, результат инвертируется; при проверке
   остаток должен быть 0xCF. Для UIH — по Address/Control/Length, для остальных типов — плюс данные.
4. **N1 берётся из команды AT+CMUX** (4-й параметр, по умолчанию 31), и длинные данные режутся на кадры ≤ N1.
   Отдельное поле «N1» в UI не нужно — оно не может расходиться с тем, что получил модем.
5. **Длина 2 байта** нужна только при N1 > 127; поддерживается в обе стороны.
6. **MSC после открытия канала.** Многие модемы (Quectel, SIMCom, u-blox) не отдают данные в канал, пока не получат
   MSC с RTC/RTR. Терминал отправляет его сам и отвечает на MSC модема.
7. **Закрытие MUX:** DISC для каналов данных, затем CLD. Без этого модем остаётся в MUX и не понимает AT до перезагрузки.
8. **Перед AT+CMUX отправляется `AT`** (до 3 попыток) — проверка связи/автобода; опция «Модем уже в MUX» пропускает
   AT+CMUX, если модем остался в MUX после сбоя.
9. **Вкладки не закрываются крестиком** — канал нельзя «потерять»; их можно только перемещать, выносить и разделять.
10. **Синхронизация записи** — `SemaphoreSlim` на порт (один кадр = одна запись), плюс замок на канал, чтобы длинная
    посылка, нарезанная по N1, не перемежалась с другой посылкой того же канала. Цикл чтения никогда не ждёт этих замков,
    поэтому flow control модема не может вызвать взаимоблокировку.

## Статус проверки

* Ядро протокола покрыто автотестами (40 шт.): эталонные кадры из документации Quectel/SIMCom, разбор с мусором,
  битыми и разрезанными кадрами, 0xF9 в данных, полный цикл сессии против эмулятора, конкурентная запись из разных каналов.
* WPF-интерфейс собирается, но в этой среде (Linux) не запускался — перед использованием проверьте его на Windows,
  начав с «Эмулятора модема».
* На реальном модеме не проверялось. Если модему нужны особые параметры, укажите их в поле «Команда»,
  например `AT+CMUX=0,0,5,127,10,3,30,10,2`.
